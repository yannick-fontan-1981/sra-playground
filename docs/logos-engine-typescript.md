# Logos Engine: first native TypeScript milestone

This document records the first laboratory milestone. The subsequent
[browser agent milestone](sra-agent-browser.md) connects the same kernel and
the V7 experiment program to live game observations through the SRA Agent tab.

## What runs

`/reasoning-lab.html` executes the V7 acquisition program in a browser Web Worker.
It reads controlled observation events, builds hypotheses, combines compatible
hypotheses, and revises knowledge when supporting evidence or a counterexample
arrives. The program tree and the execution trace refer to the actual compiled
instructions used by the interpreter.

The source reference is `agents/yf_arc3_v7` from
`yannick-fontan-1981/ARC-AGI-3-Yannick-Fontan` at
`786dcf51ca57773d8e3a8948ce9ea3655e7baf8e`. The reference bundle preserves the
original SRC and declarations, and contains the IR generated by the real V5
Python compiler. It is not an independently rewritten acquisition algorithm.

This milestone is a controlled reasoning demonstration. The existing game's
`AGENT_STATUS.available` was false in this first laboratory release. There is no claim of a completed game,
an ARC score, a complete V5/V6/V7 port, or a full SRC text compiler in TypeScript.
The current lab is an inspector; it does not yet edit program nodes.

## Modules and responsibilities

| Module | Responsibility |
| --- | --- |
| `src/logos-engine/ir.ts` | Types for the existing compiled SRC representation and compact trace events |
| `src/logos-engine/interpreter.ts` | Validate the complete module, execute supported statements, enforce execution limits |
| `src/logos-engine/canonical.ts` | Canonical values, deterministic equality and SHA-256 identities in the supported domain |
| `src/logos-engine/kernel.ts` | The V7 mechanical primitives, immutable revisions and chained knowledge deltas |
| `src/logos-engine/v7-runtime.ts` | Run the real generator and activation workflows; commit completed cycles atomically |
| `src/logos-engine/create-runtime.ts` | Construct a runtime and fingerprint its loaded declarations and IR |
| `src/logos-engine/lab-worker.ts` | Keep reasoning off the UI thread and support cooperative cancellation |
| `src/reasoning-lab.ts` | Experiment controls, actual program tree, knowledge inspector and trace presentation |
| `reference/v7/<commit>/bundle.json` | Pinned original program, compiled IR, declarations, provenance and demonstration events |
| `tests/fixtures/v7-reference.json` | Python-generated expectations used only by tests, never by the production runtime |

The interpreter supports the subset used by these V7 programs: `CALL`, `IF` /
`ELSE`, `FOR_EACH`, `NEXT` and `STOP`, plus their literal/reference/list/call
expressions. It validates the entire module, including unexecuted branches.
Unknown primitives and unsupported constructs are errors. No `eval`, dynamic
Python execution or inference service is involved in the TypeScript lab.

Knowledge is a graph: nodes can refer to shared nodes. The displayed program
tree is a structured view of the compiled control flow. Program nodes,
knowledge nodes and trace events retain their different semantics; they are
not flattened into one interchangeable node type.

## Reproduce locally

Node 22.18 or newer is required by the repository. The verified environment for
this milestone uses Node 24.22.1, TypeScript 5.9.3 and Python 3.12.14.

```sh
npm install
npm run demo:logos
npm run demo:logos -- renamed
npm run demo:logos -- scope_isolation
npm test
npm run typecheck
npm run build
npm run dev
```

Open `/reasoning-lab.html`. Step through an experiment with **Next observation**
or use **Run experiment**. Reset starts a fresh knowledge memory. The final
event in the discovery experiments repeats the preceding transition to check
that repeated evidence does not create another graph revision.

The bundle is a static same-origin asset. Runtime results are computed on the
visitor's device, and the Python golden fixture is not loaded by the lab.

## Parity and provenance

The comparison target is execution of the original Python V7 runtime, not a
second handwritten version of the same algorithm. The reference export records
the exact source revision and the SHA-256 of each included original file.
Its export script documents the reference environment and any normalization.

The validation on 7 November 2026 passes **54 tests**: 22 existing game parity
tests and 32 interpreter/kernel/reference tests. The V7 differential suite
compares all **26 retained states across five scenarios**, including masking
by node identity and by kind, followed by reactivation. It checks the entire
ordered delta history, node revisions, evidence, SRC causes, availability,
receipts and instruction counts. Each implementation's raw audit chains are
also recalculated independently.

Two semantic mismatches found during this comparison were corrected: the
selection order now follows Python's sorted `FrozenMap`, and instruction
accounting includes completed IF frames and loop iterations. Trace events
distinguish `statement` from `frame_complete`; neither is a fabricated call.
The discovery scenario's instruction counts are 19, 85, 164, 210, 262 and 48.

The browser check exercised a complete experiment, node inspection, the actual
48-event final trace, scenario selection, one-observation stepping and reset.
The final discovery state has 19 nodes: three hypotheses (two contradicted),
one suspended composition, observations, transitions and questions. Repeating
the last event creates zero new deltas. A captured result is stored in
`docs/logos-engine-v7-lab-20261107.jpg`.

To regenerate the oracle from a local checkout containing the pinned files:

```sh
python scripts/export-v7-reference.py --python-root /path/to/ARC-AGI-3-Yannick-Fontan --check
```

The checked source manifest lists 101 original files. The original Python
loader supplies two explicitly documented namespace packages to avoid unrelated
reexport initializers. No compiler, scheduler, runtime or primitive is replaced.
This validates the selected workflows, not full application startup.

Python and TypeScript are different implementations. Their source fingerprints
must not be presented as identical. Comparisons normalize only the explicitly
documented implementation fingerprints and compare actual knowledge contents,
node identities, revision numbers, evidence, contradictions and delta causes.

`createV7Runtime` computes a SHA-256 over a manifest encoded as UTF-8
`JSON.stringify`: implementation version, encoding name, reference commit,
loaded knowledge declarations and compiled programs. This fingerprint is not
a hash of the shipped JavaScript binary and is not the Python source digest.
The receipt's workflow hash uses the Python registry's exported transitive
source hash when available, otherwise the compiler's semantic IR hash. Its
`workflowHashKind` field records which kind it contains.

## Deliberate limits

- Observation values use strings, booleans and safe integers. Negative zero,
  fractional, non-finite and unsafe integer observation values are rejected. Python's
  distinction between `1` and `1.0` cannot be silently reproduced by a plain
  JavaScript number. Unused fractional declaration metadata is preserved.
- Execution has instruction and elapsed-time limits, periodic yielding and
  cooperative cancellation. Caller options cannot raise a DRM-declared limit.
  A stopped or failed cycle must not publish a partly updated memory.
- Traces record instruction locations and compact outcomes. They do not copy
  the whole knowledge graph at every instruction.
- The browser lab runs small reference experiments. It is not a performance
  assessment on large graphs or long game sessions.
- Compiled statement IDs identify positions in this program revision. They
  are not durable editing identities across a source rewrite.
- The game runtime still uses its original Python engines in Pyodide. This
  TypeScript reasoning worker does not change those game engines.

## Next milestone: an editable program representation

Keep the executed IR as the contract and add an authoring layer with stable
node IDs, source locations, typed parameters, validation and explicit versions.
Start with editing the parameters/conditions of a small generator. Apply edits
between completed cycles, show a diff and rerun the same reference scenario.
An invalid edit should leave the previous valid program available.

Then connect the public observation stream of one Playground game through a
separate adapter. Keep pixel/object observation, knowledge acquisition, action
proposal and game action execution as explicit boundaries. Record the resulting
trace before broadening the port to planning and policy components.
