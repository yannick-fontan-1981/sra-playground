## Generic native extensions

### Current point binding

The strict source guard refuses a point when multiple current descriptions
match its support patches. In the retained second attempt, a band component
and a point region describe the same physical point in level 2. The native
guard permits the already selected witness only when its candidate, patches,
coordinates, palette value, bounds and signature agree across those
descriptions, and its selected component is uniquely present in the current
view. The original refusal remains in the binding receipt.

This guard predicts no effect. The common authority retains the binding
evidence before ordinary WHY/ACT authorization; the next actual public return
determines what was acquired.

### Bounded ReductionTransport search

The third attempt reached two levels but exhausted memory while the common
caller considered ReductionTransport at the next scene. The native profile now
bounds that search at 8,192 retained states and a 16,384-entry frontier, with
cooperative cancellation. Bounds apply before insertion. A resource bound
returns explicit `unknown`, without a partial route or an impossibility claim,
and the refusal is scoped to the current observation.

The default source algorithm remains unchanged. On the retained diagnostic
scene, the independent source measurements establish a large compatible model;
they do not prove it unsatisfiable. The diagnostic and actual failed execution
remain separate from subsequent successful test results.

### Receptions visible inside an actual public packet

One command can return several visible animation frames. Comparing only the
first and final images can miss a shape passing through stationary framed
receivers. The native packet helper measures those public frames in their
actual order. It requires a globally unique nonuniform shape, stable source
and arrival positions, axial displacement, matching frame extents and borders,
a previously uniform receiver, preserved local boundaries and support geometry
outside the swept region of the directly moved span.

Ambiguous, missing, transiently corrupted, incomplete or over-budget evidence
produces no partial receipt. This helper neither invents an intermediate
command nor infers a universal control law. The actual outer command remains
the only executed action. Its packet witness links each measured reception
to that command, transition, frame hashes and observed trajectory.

These receipts occupy an explicit native annex in the immutable v2 family
checkpoint. The six-field source state remains separate. At a level boundary,
the receipts become historical evidence with no current action authority.
Restoring a source-only checkpoint clears the annex; restoring a full native
checkpoint validates both parts atomically.

### Receptions after a support has settled

A separate, opt-in measurement handles a reception that becomes visible only
after the directly moved support has stopped. It identifies a framed
appearance by its exact mask, extent, interior value and border value. This
contextual identity is distinct from the original extractor's globally unique
monochrome component identity; it is not a claim about an invisible physical
object.

The public packet must show a unique contextual appearance continuously, two
stable source frames, a monotone axial trajectory into a previously uniform receiver,
and at least two stable arrival frames. Both endpoint patches of each relevant
outer support must remain literal throughout the measured phase. The helper
chooses the first eligible settlement whose complete receiver collar has
returned to its observed value; both lateral sides must remain unchanged in
every intervening frame. This permits a valid earlier settlement to be
retained before a later, independent arrival changes the surroundings.

These receipts explicitly retain the signed source-to-receiver vector and
are marked `native_directed_composition_only`. They do not enter the original
candidate generator, which does not preserve that direction in its reception
analogy. They remain observed transitions, without an intermediate command,
causal control claim or current release authority.

### Current receivers and missing control prerequisites

The original reception-locus generator considers uniform destinations inside
its loop over typed terminal relations. Consequently, an actual reception into
an empty uniform frame cannot by itself open a current task when no matching
terminal shape is visible.

The explicit native question extension starts from an acquired current-epoch
uniform-reception receipt. It requires a unique current source, a current
uniform receiver, a revalidated moving support, an exactly matching visible
gap patch and the same observed source-to-receiver orientation. It performs
no palette substitution, rotation or inferred reversal.

When the required side has a compatible offset established by actual
point-motion observations, these measurements support a conditional reception
question. When that offset is missing, the extension may restrict a general
calibration choice to an existing, untried source-generated point on the
required side of the same current support. Its source facts and physical
candidate are preserved exactly. The effect remains unknown until execution.
The engine then measures the new view and recomputes the question.

The sixth actual campaign exposes the same missing-control condition for a
typed analogy already supported by the source's current mask-pair rules.
After action 46, a current pair has the exact observed downward gap and a
revalidated source support, but only the opposite control side has been
observed. The dependency rule also examines these source-compatible typed
analogies. It preserves the actual uniform-reception receipt and separately
identifies the current mask-pair hypothesis; it does not turn an analogous
typed reception into an observed event. The required calibration remains an
unchanged current source offer. The source policy can propose the reception
only after the actual return supplies the missing control evidence.

The seventh campaign exposed a necessary distinction in this coordination:
an unknown control supported only by a typed analogy must not displace a
source-selected point motion already bound to an observed offset. Its first
divergence acquired the new control successfully, but also moved the payload
into a differently marked receiver and changed its visible border. The
corrected ordering preserves the source's revalidated motion question ahead
of a purely typed calibration. That calibration may still precede an
unqualified interface exploration. Directly observed uniform-reception
prerequisites retain their separate evidential basis. No global caller or
source policy ordering is changed.

Each selection retains the source choice before restriction, the current
dependency, its precise receipt and span references, and the selected point.
The guard recomputes this evidence before release, including when the source
guard already admits the physical point. Neither the dependency nor a packet
subframe can authorize an action on its own.

An independent review also found two incompatible reception tasks sharing one
physical point. The corrected helper refuses native questions at ambiguous
points, counting both native tasks and current source loci without rewriting
source facts. A retained synthetic contract reconstructs both spans through
the source transition and acquisition functions, rejects the colliding point,
keeps a separate unambiguous point and verifies that a newly ambiguous
proposal fails its current guard. This is a controlled geometry test, not a
game result.

### A current intermediate receiver

Two currently corresponding shapes can share a moving support. Translating
that support preserves their relative position, so a direct alignment cannot
resolve that relation. The native composition extension measures this
condition explicitly and asks whether a separately supported uniform receiver
can serve as an intermediate destination. The correspondence and any
inter-mask reuse remain hypotheses; no analogous reception is inserted into
the observed history.

Every question carries the current source, its co-carried marker, the selected
uniform receiver, their bound supports, a literal visible gap and the exact
signed vector of an acquired receipt. If a reception is already geometrically
ready, the question concerns one current point. Otherwise, a preparation can
move the uniform receiver toward a currently visible gap anchor. The marker's
projected position is explicit when the source support is the one moved. No
second action is committed: all relationships are measured again from the
actual return.

The extension uses the source's actual point-span measurements over the full
history. A unique current locus may use the source's revalidated-motion
projection. Conflicting observed offsets remain explicit competing hypotheses
and can support only an exploratory point question with the weaker, truthful
band facts. Selecting one prototype never fabricates a unique binding or an
established reception. Current guard remeasurement and physical-point
ambiguity checks apply to both kinds of question.

This coordination has an explicit native early admission for the measured
composition. It does not alter the original policy declarations or the global
family order. Within this composition, an already ready reception precedes a
preparation, and a genuinely unique current control precedes a question with
competing control hypotheses.

There is no stored action sequence, game identifier, fixed level branch,
authored coordinate route or access to private game state in these helpers.
Pixel values and coordinates are measured from the current public observation;
an evaluation game's name belongs only to the campaign harness.

## Lossless evidence storage

The 24 v52 JSON reports larger than 1 MiB are stored in the source repository
as gzip files. Their 608,709,486 original bytes compress to 41,609,814 bytes,
a 93.164% reduction. The
[storage manifest](native-campaigns-v52/evidence-storage.json) records each
original and compressed path, byte count and SHA-256. The original reports
remain present and unchanged in the working checkout; only their exact paths
are excluded from Git in favor of the compressed representation.

After a fresh checkout, run `python scripts/restore-v52-evidence.py` to restore
the original report paths. The script checks both compressed and decoded
hashes, skips an identical existing file and refuses to overwrite a divergent
one. `--verify` performs the same stream checks without writing.

The [storage verification](native-campaigns-v52/evidence-storage-verification.json)
restores all 24 reports into an initially empty temporary root and verifies
byte-for-byte identity. A second restoration is idempotent, and three negative
cases confirm rejection of invalid evidence or conflicting destinations.
All 196 preexisting evidence files, including the final campaign validation
receipt, are unchanged. These are storage checks, with no additional game,
native-agent or release-test execution.
