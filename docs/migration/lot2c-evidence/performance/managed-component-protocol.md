# Absolute entry and managed morphology component costs

This protocol is declared before execution. It supplements the unchanged common STCK/SMLP comparison and its 10% budget; it does not replace or widen that budget. The published V62 implementation did not expose retained-method managed projection and search through this native producer. The new work therefore receives absolute timings, with no zero-cost baseline, before/after ratio or claimed speed improvement.

The runner is `scripts/measure-native-morphology-managed-costs.mjs`. It measures calls to five component entry points from the newly connected source domain: `projectManagedLayout`, `searchManagedAccess`, `measureMorphologyRoutes`, `approachMorphologyEntry` and `resumeMorphologyEntry`. They own no retained knowledge. The two entry consumers deliberately enrich the current facts supplied to them, as described below. None of these calls dispatches a physical action; a returned plan remains a proposal rather than physical authority.

## Reference and explicit input boundaries

The nine managed cases come from `tests/fixtures/v6-morphology-managed-reference.json.gz`, generated by `scripts/export-v6-morphology-managed-reference.py`. Three additional entry cases come from the stabilized `tests/fixtures/v6-morphology-entry-reference.json.gz`, generated by `scripts/export-v6-morphology-entry-reference.py` and its declared shared public-canvas generator. Both exporters execute the pinned original V6 at `786dcf51ca57773d8e3a8948ce9ea3655e7baf8e`, with no source modification, AST transformation, monkey patch, native callback or native expected output. Each hashes all 1,786 original files before and after reference generation. No game engine, private game state, level definition or stored game solution supplies an input.

These are **component-boundary fixtures**. They do not start a fresh Kernel and do not claim that retained methods, collection events or meter forecasts were acquired during the measured invocation. The setup constructs native snapshots and the actual `CollectionEvidence` owner outside the measured interval. The real owner's `evidence_for` method remains unchanged; it is not replaced by a canned lookup.

## Repetitions and measured quantities

Each case runs three warmup calls followed by twenty measured calls in one warm Node process, for 36 warmups and 240 measured calls overall. Calls reuse the same component input premises. The runner compares a structured clone of those complete fixed premises before and after all repetitions to detect mutation. It does not accumulate synthetic acquired knowledge between calls.

Entry approach and continuation enrich their `facts` argument in the original source. Before each entry call, the runner creates a fresh working copy of the same initial measured facts, outside the timed interval. The consumer receives this working copy, and the runner compares its enriched contents exactly with the original expected facts after timing. The fixed initial-facts template, retained method, pending record, snapshots and history must remain unchanged. This explicit facts-output contract is not misreported as an immutable consumer or hidden acquisition.

Each measured interval begins immediately before invoking its component and ends immediately after awaiting its return. The interval includes that invocation and its return scheduling. For asynchronous geometry and entry calls it also includes their awaited native digest work. All input construction, original-fixture decompression, source hashing, snapshot creation, collection-owner setup, fresh entry-facts copying, result assertions, input-immutability checks and receipt creation occur outside the interval.

Every measured result must match the original expectation. Search options, geometry facts/plans, entry plans and entry facts enrichment are compared exactly, including their order and conditional witnesses. Only the direct projection's `uncertain_edges` array is compared as a multiset: the original emits this field by iterating an unordered set of vectors, and search subsequently consumes it as an edge map. This comparison does not reorder route options or search priorities.

Raw elapsed wall-time samples are retained. The receipt reports count, median, minimum, maximum and empirical nearest-rank p95 for each twenty-sample case. Repeated warm-process samples share the same evidence and are correlated; p95 is not a confidence interval. No CPU time, allocation bytes, copy count or physical action cost is inferred from these intervals. Search states and result counts qualify the finite work performed; they are not converted into a fabricated cost per reasoning operation.

Geometry already includes its own ordinary route measurement, managed projection and finite search. Entry approach includes its internal geometry measurement and revalidation work. The separately measured projection, search and geometry fixtures have different inputs. Their times must not be added to one another or to entry-approach intervals as an additive decomposition.

## Costs and claims outside scope

This diagnostic excludes whole-caller planning and arbitration, morphology policy evaluation, WHY/ACT authorization, the common acquisition/persistence path, checkpoint restoration, service continuation, worker transport, inspector/browser rendering, hosting and live game execution. It does not measure initial learning of a method or prove that a fresh Kernel naturally chooses the same composition.

The campaign evidence and common loop comparison remain separate. A public synthetic conditional composition is not an ARC game success, a new completed level, a replacement for cold acquisition evidence or a complete transfer claim for the original caller. The explicit use of fixtures is a declared consumer boundary; it must not be described as a game trace replay through the Kernel.

Finite-search completeness is preserved in both functional assertions and reported outputs. A search that exhausts its state bound is incomplete; lack of an option in that case is not a proof of impossibility. The timing sample does not change this status or extend the configured bounds.

## Frozen inputs and reserved window

Execution waits until the real-game campaign and the separate common-loop comparison have ended, then uses a reserved project measurement window. Other agents may read files or edit documentation, but must not intentionally run tests, builds, campaigns or fixture generation concurrently. The host is shared; external CPU activity is not separately measured. Any known project overlap must be reported rather than silently discarded.

The runner fingerprints its script, this protocol, both reference fixtures, their original-source exporters, the entry exporter's declared shared generator, the manifest and used original source files. It records the full native inventory before and after and refuses a changed native inventory, changed input or changed protocol. The receipt's native digest identifies the actual measured checkout even while it remains uncommitted. A Git-head field alone is not the native identity of a changed checkout.

The output path must be unused; the runner refuses overwrite. A failed attempt's output/log should be retained under a distinct attempt name. No optional retry is used to select a faster result. Any subsequent run must have a stated concrete reason and preserve the preceding attempt.
