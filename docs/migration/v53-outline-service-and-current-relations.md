## Explicit native composition

The native public-transition annex retains the immediately preceding actual
public final raster and its scope, separate from the seven source state fields.
This supplies the already-existing V5 previous-raster measurement with evidence
the original V6 wrapper did not pass. After an actually selected access question,
the annex can also retain its bounded measured `access_relation`. Its prior
observation, row hash, scope, selected command and guard must match the actual
transition. Each selected primitive refreshes that relation from the current
public return; it contains no recursive chain of prior access witnesses or
stored future route.

At an official boundary, a separately labeled current-only recalled context
has no preceding transition: `before` and `command` are null. It can support a
directly measured current motif, but cannot supply the temporal evidence for a
missing-marker fallback. No intermediate animation raster is treated as the
current public final observation.

The optional annex has a narrower hash domain than the common observer: it
binds the 16-character JSON public-frame identifier to retained raster bytes.
The producer now declines other caller identifiers, including the existing
64-character NumPy-compatible `rowsDigest`, and clears any stale annex while
ordinary source acquisition continues unchanged. It does not rewrite those
identifiers or reinterpret one hash scheme as another. Restored annexes retain
strict byte, hash, scope and selected-goal validation; an invalid binding
within the supported domain still fails. The production-domain regression and
strict-restoration counterexamples are covered by
[`v6-outline-public-context.test.ts`](../../tests/v6-outline-public-context.test.ts).

A current service question can be preferred only after the common caller
corroborates its current observation, actual trial record, effect inventory and
ordinary guard. Each question releases at most one primitive, then measures
the actual return again. A source declaration, historical method or geometric
proposal does not independently authorize physical execution.

A separate native access question approaches a unique currently measured
visual relation when the transferred service has no applicable proposal and no
transferred recovery question applies. An actual historical local method
supplies a conditional prior, not a current observed effect. The helper
distinguishes two control bases:

| Control basis | Required evidence and directional mapping |
| --- | --- |
| Current reacquired control | Exact current outline plus actual current-scope translation evidence; measured action deltas take precedence, and only missing mappings may use a revisable interface prior |
| Current unique revalidated recalled-control hypothesis | Exact current outline, unique source recall and historical control evidence; no current deltas are claimed, and directions use only revisable interface priors |

Conflicting measured deltas are not replaced by a prior. The target also has
two explicitly different evidence bases:

| Question | Current target and temporal requirements |
| --- | --- |
| `current_announced_cell_access_question` | The visible singleton marker cell in one exact current same-value compact-body/marker/perimeter correspondence |
| `current_observed_body_access_question` | The actual current solid-body cell, reidentified with a unique same-value perimeter after an adjacent actual public transition in the same epoch and score |

The observed-body question requires either the exact preceding selected access
relation or an independently measured body/marker/perimeter relation in the
previous public raster. The current body must be unchanged or have moved
exactly to the preceding observed singleton cell. The latter uses V5's
observed-announcement premise; it does not predict future movement. Arbitrary
displacement, stale scope, an ambiguous relation or a nonsolid current body
cannot supply this question. When the marker is absent, `marker_cell_bbox` and
`relation.cardinal_marker` remain null. Successive missing-marker frames can
refresh the bounded relation through actual selected primitives, without
inventing a current marker.

Each access question chooses at most one in-bounds, lattice-aligned direction
that reduces distance to its current target, then measures the actual return.
It establishes no obstacle-color rule, safe route, autonomous motion, contact
consequence, terminal rule or guaranteed progress. This composition is a native
extension and must not be reported as unchanged V5 or V6 behavior. Its focused
contracts and caller integration are covered by
[`v6-outline-access.test.ts`](../../tests/v6-outline-access.test.ts) and
[`v6-outline-recovery-integration.test.ts`](../../tests/v6-outline-recovery-integration.test.ts).

### Current arrival and a conditional local intervention

Attempt7 adds the explicit native
[`v6-outline-arrival.ts`](../../src/logos-engine/v6-outline-arrival.ts)
composition. It requires an actually selected, guarded observed-body access
primitive whose measured return places the reacquired contour at that prior
body cell. The previous solid body and compatible perimeter must be exactly
revalidated from the preceding public raster. The current perimeter must
remain unique and unchanged; some same-value inset pixels must remain visible
and other inset pixels must have visibly changed. Outline-border replacement
alone is insufficient.

The resulting question retains only those visible measurements. It leaves
`complete_current_body` null and does not establish body survival, current body
identity, capture or any operator effect. It is stored as `recovery.contact`,
not as a new access relation. Its active goal is
`goal.reveal_action_conditioned_structure`, with the existing accompaniment
goal retained as the terminal hypothesis.

The source motivation is V5's
`principle.effectful_local_operator_transfers_to_new_changed_bfs_endpoint` and
its related changed-endpoint projection. The original rule requires an
actually completed standard BFS endpoint. This native question instead uses
the actual return of one selected access primitive and explicitly records
`exact_source_projection_matched: false`. It is not an additional exact V5
declaration transfer.

Before dispatch, the service must revalidate exactly one currently available
input with positive historical local-method evidence, a complete current
effect inventory with no competing observed local operator, and an untried
actual caller context. An available input with no observed effect remains
unknown; historical evidence is not inserted into the current effect
inventory. Ordinary preservation and WHY/ACT still apply. Only one local
primitive can be released, with no predicted effect, before another real
public observation is required. The focused geometry contracts are in
[`v6-outline-arrival.test.ts`](../../tests/v6-outline-arrival.test.ts); the
existing recovery integration test additionally checks the actual retained
attempt6 prefix without reusing its old next return for the newly proposed
command. This composition was absent from frozen attempt6.

## Why the next level exposed a reuse gap

The retained ESCT public observations show a useful distinction. Level 1 has a
larger enclosure compatible with the controlled contour. Level 2 removes that
enclosure and starts the control away from the visible body/marker/perimeter
relation. Reacquiring movement therefore does not automatically prepare the
previous service.

In the retained attempt3 trace, L1 succeeds in 16 actions. At L2, current
movement is reacquired, but the strict source service finds neither a compatible
locus route nor an already aligned accompaniment. A diagnostic using the
unchanged V5 recovery helper on 54 acquired public scenes through action 64
finds no L2 rejoin witness. The existing post-intervention recovery rules cannot
be relabeled as initial access by dropping their premises.

The same diagnostic does find a real source rejoin after L1 action 12:
`ACTION5` was the actual previous input, one announced correspondence remains,
and the one-step rejoin is `ACTION1`. This establishes a current relation,
not a stored solution sequence.
