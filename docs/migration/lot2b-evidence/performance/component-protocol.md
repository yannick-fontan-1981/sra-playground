# Absolute control and attention diagnostic

This scope is declared before execution. It supplements, and does not change, the matched STCK/SMLP budget. No V61 denominator is constructed for a consumer that was absent from V61.

## Public origin and current measurements

The input starts with the `family.current` public raster in `v6-morphology-measurements-reference.json.gz`, padded with zero pixels to 64 by 64 exactly as in `v6-control-attention-kernel.test.ts`. A fresh real native runtime and `V6AgentService` start with empty acquired knowledge. Five plain public inputs are available. For each of two released actions, a finite synthetic public protocol moves the four color-9 pixels two columns to the right and returns the resulting frame. It does not give the runtime roles, an expected action, a route, a decision, history or a remembered method.

The real morphology producer must first retain the current pair with an unmeasured control, and after the first acquired public return retain a replication question. The diagnostic captures the actual native observation, current measured decision, caller state and reasoning state after this second decision. It also obtains the actual public observation and current measured decision after the second acquisition. These checkpoints are generated by real acquisition during this diagnostic, not imported from an expected fixture result.

The two acquired actions are a synthetic protocol, with zero completed game levels. They are not an ARC game success or evidence of a new game solved. Setup is recorded separately from component-call timings.

## Cases and boundary inputs

Each case uses the actual `NativeCallerCoordinator`, `ObservedFrontier` and `AttentionMemory`; no method is replaced by a decision or acceptance double. The source consumer fixture has deliberately synthetic morphology premises and is therefore not used as a measured morphology decision.

| Case | Measured call | Scope |
| --- | --- | --- |
| replication inspection | `acquireControlForTarget(..., inspectOnly)` | Actual acquired translation and actual frontier admission check |
| replication proposal | `acquireControlForTarget(...)` | Actual frontier proposal and caller delta persistence |
| unrelated unbound information | `informationOffer(...)` | Actual current-control inspection and preservation of its attention witness |
| same-action information | `informationOffer(...)` | Information receipt annotated with its actual control question |
| focused replication proposal | `acquireControlForTarget(...)` | Actual pending attention prepared by the preceding admission path |
| parent return | `attentionParentReturnOffer(...)` | A real matching observed attention return, consumed once by `prepare`, against the actual newly measured decision |

The information cases add one explicit offer through the existing `additionalOffers` parameter. Its question/relations/predictions and unbound-return shape come from the original-source consumer fixture; its observation reference, epoch, evidence and action are rebound to the actually acquired current public context. One case uses the acquired control action and one uses the first distinct available plain action. This is a declared information-producer boundary input, not a claim that the display producer naturally offered that question in this raster. The real points and display producers still run. Their outputs are not suppressed.

The parent-return case opens the actual acquired replication question, observes the second real public transition through `AttentionMemory.observe`, and calls `prepare` at that return. It uses the freshly measured post-return morphology decision, even if that decision now declines further control acquisition. Its exact resulting branch is reported; a gated return must not be described as a positive follow-up proposal. No status, pair or policy is changed to force this branch.

## Repetitions, copies and work

There are three warmup calls and twenty measured calls per case in one warm process. Before each call, new reasoning memory and caller objects restore the same captured checkpoint. Required attention setup also starts from this restored state. Checkpoint restoration and case preparation are timed separately from the named operation; preparation does not accumulate across repetitions.

Transparent instance wrappers call the original methods with the original inputs and return values. They record nested caller, frontier and attention method counts and durations, labelled separately for preparation and the named operation. Thus the parent-return opening, observation and single-use consumption remain visible as preparation work. An outer operation interval includes wrapper overhead. Nested intervals overlap and must not be added to the outer interval. Correctness assertions and output projection occur after operation timing.

A separate fresh-state census call per case counts calls to the platform `structuredClone` during restoration, preparation and the named operation. Clone interception is disabled for the twenty timing samples. This counts calls, not bytes, deep object count or all copying: array slices, spread syntax, JSON encoding and internal implementation copies are outside this census. Method counts, semantic operations and copy counts are reported as distinct quantities, never converted into an artificial cost per reasoning operation.

Raw samples are retained. Medians, minimum, maximum and empirical nearest-rank p95 are reported for twenty samples. Samples share the same captured evidence and warm process, and are correlated; p95 is not a confidence interval. This absolute restored-component diagnostic excludes fresh acquisition cost, full runtime selection, WHY/ACT authorization, worker transport, browser rendering and live game execution from its component intervals. The setup receipt shows that the state and decisions were originally produced through the real common runtime.

The runner fingerprints its fixtures, declarations, protocol and script, and records the native inventory before and after. It refuses to overwrite receipts and retains any failed attempt. Execution requires a reserved project measurement window after fixture generation and tests have ended.
